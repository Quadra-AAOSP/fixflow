# i18n Conventions — FixFlow Mobile

Rules that keep `en`/`zh` catalogs from drifting apart. The test suite (`tests/i18n-catalogs.test.ts`) enforces most of these mechanically — run `npm test` after any catalog edit.

## Where things live

- `constants/i18n.ts` — i18next init, locale persistence to SecureStore, `setLocale()`
- `constants/resources/en/common.json` / `zh/common.json` — the only two catalogs
- `constants/i18n.ts` sets `interpolation: { prefix: '{', suffix: '}' }` — **single braces**, not the i18next default `{{ }}`

## Rules

1. **Every key exists in both files at the same path.** Parity is a test; CI would fail otherwise.
2. **Single-brace placeholders only**: `t('x', { count })` renders `{count}` — never write `{{count}}`.
3. **Never translate at module scope.** Call `t()` inside components/hooks, or use the `i18n` instance in non-component modules (e.g. `utils/maintenance.ts`). Module-scope `t()` captures the locale at import time and never updates.
4. **Placeholder parity**: a `{var}` present in the `en` value must also appear in `zh` — except `{plural}`, which is an English plural-suffix sentinel that Chinese legitimately omits.
5. **No blank values** — an empty string renders as missing text.
6. **No HTML/JSX in values** — plain text only.
7. **New namespaces**: nest under the screen's existing root (`reports.detail.*`, `assignments.*`), don't invent new top-level groups without a reason.

## Adding a string

1. Add the key to `en/common.json` (2-space indent, no trailing commas)
2. Add the same key to `zh/common.json` with natural Simplified Chinese
3. `npm test` — parity + placeholder checks must pass
